# Android and iOS browser CI

`mobile-browser.yml` starts Android Chrome in an API35 x86_64 emulator on Linux
and Safari in an installed iPhone Simulator on macOS. It serves only test and
cache-module files from a temporary loopback origin; no production service or
private models are used. The browser executes the real `model-cache.mjs` and
`sha256.mjs` modules, native Cache Storage, streams, workers and PNG encode/decode.

Eight mandatory checks:

1. Module worker computes a known SHA-256 vector.
2. Wrong download bytes fail integrity and never commit.
3. A cancelled partial stream does not commit; retry succeeds.
4. Concurrent acquisitions share one transfer.
5. Corrupt retained data is detected and repaired.
6. A synthetic 1024px PNG survives encode/decode with exact pixels.
7. Portrait JPEG EXIF orientations and bounded crop geometry.
8. A full page reload retains model bytes and reuses them under a changed asset
   URL with acquisition deliberately disabled.

Acquisition uses real HTTPS fixture transfers from the local server, the built
`browser-model-manager` package, native Cache Storage/OPFS, and real acquisition
grants. Corrupt cache contents and JPEG/PNG files are planted inputs. The server
records transfer counts, partial bytes precede cancellation, and the offline URL
returns 410 if it is contacted after reload. No fetch implementation is replaced.
The tiny asset validates semantics, not large-model memory use or CDN/range behaviour.
Reload persistence is not OS/browser restart or a guarantee against eviction.
The PNG fixture is not generated by the model.

The server creates a one-day localhost TLS certificate. Its new task-owned iOS
Simulator trusts that root; the Android emulator explicitly ignores certificate
errors (never point this runner at the physical phone). The desktop-only component
smoke uses a persistent browser profile: headless WebKit's ephemeral context loses
even a native Cache Storage entry on reload. It is not Safari/iOS evidence.

Reports record exact component source hashes, checkout SHA, runtime/device and
browser identity, partial progress, screenshot and Android logs. Missing handshakes,
missing/duplicate cases, failed tests and timeouts fail the job. No unsupported
feature is silently counted as a pass. `e4eExecuted` and `inferenceExecuted` remain
false; simulator/emulator evidence cannot qualify a physical device.

Run the lightweight controller checks with:

```sh
python3 -m unittest discover -s apps/web/tests/mobile -p 'test_*.py'
```

On an isolated CI machine with Android Emulator already booted:

```sh
python3 apps/web/tests/mobile/run.py --platform android
```

On macOS with Xcode and a downloaded iPhone Simulator runtime:

```sh
python3 apps/web/tests/mobile/run.py --platform ios
```

The iOS runner creates and removes its own Simulator. Build the package first with
`npm run build -w packages/stylegan-js -w packages/browser-model-manager`. Android uses the already
booted CI emulator and changes Chrome's first-run configuration; do not point it
at a personal phone. Correctness runs share compute. Only timing campaigns need the bounded
`autoresearch/run.py --exclusive gpu-timing` admission.

## Next coverage layer

**16 September operator direction:** Core mobile CI is intended to verify the
actual new-site version specified by the delivery plan. These component tests are
its starting layer, not its final acceptance scope. Keep research experiments
separate; prefer available local compute or explicitly temporary CI workflows,
with bounded execution and retained evidence. Do not replace product workflow
checks with research screens or weaken required checks for an experiment.

Once the integrated client runtime is available, add actual UI automation and
pin the generation/e4e bundle to its source/model/fixture hashes. Run real CPU
synthesis correctness, actual photo encoding and full reconstruction, two-photo
morphs, original reuse and exports in both mobile environments. GPU absence and
loss must exercise independently qualified CPU recovery. Current tests do not
claim those workflows are implemented or tested.

Keep larger full31/photo suites in a bounded scheduled/manual inference job if
too expensive for each PR; use a smaller explicitly labelled screen per PR.
Never substitute mock inference or precomputed W+ for the missing encoder test.
Physical iPhone/Android runs still gate memory survival, sustained performance,
GPU-driver behavior and release qualification. Record simulator versions as CI
images change; they are not fixed handset profiles.
