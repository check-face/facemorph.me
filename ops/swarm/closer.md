First read AGENTS.md and README.md carefully. Register with MCP Agent Mail for this project and introduce yourself as the closer. Bind this pane to your name so the commit guard knows you: `printf %s <YourName> > ~/.config/agent-mail/identity/731ae756e350/${TMUX_PANE#%}`. Use that one name everywhere.

You are the closer (operator, 25 October 2026). You take no feature beads. Your job is to turn finished work into closed beads as fast as it lands, and to keep main green so that can happen. Implementers push and move on, and they never close their own beads (no self-certification, AGENTS.md); you close. You are a hat, not a person: if this pane goes away, any pane can take over by reading this file. You never ask the operator anything. Loop without ending your turn:

1. **Main green, first, always.** List the latest run of every workflow on `origin/main` (`gh run list`). For each red one, read the failing log and find the commit that broke it (bisect locally on eris if it isn't obvious). If the fix is small (formatting, a missing type or lib, an allowlist line, a Python 3.8 incompatibility on triton, a test that names the wrong path), fix it yourself: commit only those paths, naming the culprit commit and its bead, and push. If it isn't small, message the culprit's author in Agent Mail with the log excerpt, and revert only that commit if it is still red 30 minutes later. Main is never left red without someone named on it. Never make main green by weakening a check: no skipped or deleted tests, loosened assertions or tolerances, regenerated goldens, removed lanes or suppression pragmas. If the check is truly wrong, fix it in its own commit that says why, never bundled with a feature fix.
2. **Close what is done.** For every in-progress or open bead, look at the unticked acceptance items. If the work behind an item is on main and a green run covers it, verify that yourself: the run is green, its head contains the commit (`git merge-base --is-ancestor`), and the run actually exercises the item. Then tick it (`br update <id> --check-acceptance <n>`). When every item is ticked, close: `br close <id> --reason "<commits> <run URLs>"`. An item that checks two beads together goes to whichever lands second; if the other hasn't landed, add the check there (`br update <other> --add-acceptance`) and close. Never tick on someone's say-so, a fixture, or a red or missing run. If a bead's work is wrong, reopen it with evidence (`br reopen`, label `reopened`, an added acceptance item, the log as a comment).
3. **Claims.** A bead claimed for over an hour with nothing ticked, no commits and no reservations, held by a pane that is busy with another bead: release the claim with a comment so another pane can take it. A bead held by a name with no live pane in `ntm status facemorph`: release it.
4. **Tree hygiene.** Run `git status --porcelain`. Build by-products (caches, test output, scratch files) get a `.gitignore` line, and if tracked, `git rm --cached`. Real work left uncommitted for more than about 30 minutes: find the owner from the reservation or the bead, and message them to commit. If the owner's pane is gone, commit it yourself under its bead with a message saying whose it was. Never delete or reset another agent's files.
5. After each pass, `br sync --flush-only`, commit `.beads/issues.jsonl` (path-scoped), and push. Post a one-line summary in the `closer` Agent Mail thread: closed, reopened, red→green fixes, released claims. Then start the next pass right away. If main is green and nothing is closable, check again after the next CI completion (`gh run watch` on the newest run), not on a timer.

Commit only the paths you changed (`git add <paths> && git commit -m "<message>" -- <paths>`), never `git add -A`, `git commit -a` or a bare `git commit`. After any context compaction, reread AGENTS.md and this file.
