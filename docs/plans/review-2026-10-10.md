# Fresh review of the candidate plan — 10 October 2026

**Scope:** source/contract review of the current dirty checkout, not a new browser,
photo, GPU or installed-desktop qualification. Reviewed Product.fs, product bridge,
media/video worker, frame/original stores, analytics/reporting and current plans.
Concurrent implementation edits remain uncommitted; findings are local-source
facts, not claims about the deployed artifact. No application code changed here.

## Ready for implementation

The tagline, responsive per-face Generate placement, five-shape selector, existing
length/pinch defaults, Advanced processing override and consent copy are specified

## Concrete findings and plan corrections

1. **Infill order is not video order.** `media.mjs` uses the supplied index for
   retained-frame storage but sends frame pixels to the worker without that index.
   `video-worker.mjs` timestamps frames by arrival count. Feeding midpoint-first
   frames directly to this writer would export a scrambled morph. Separate
   synthesis/availability order from presentation/encoding order. Retain frames
   under their canonical indices and feed the encoder in path order through a
   bounded drain or later ordered pass. Do not buffer every decoded full-size
   frame merely to reorder it. Progress counts completed synthesis separately.
2. **Live scrub needs a new availability contract.** Frame-store read APIs require
   a complete morph. The slider currently constructs images for every supplied
   frame, and its cache identity is only the array length: another morph with the
   same count can reuse stale images. Add sparse frame availability, explicit
   morph identity/revision and bounded on-demand display decoding. Missing frames
   must not masquerade as generated frames. Keep one result surface: scrub while
   generating, then video or scrub according to the user's chosen mode.
3. **Restore needs an index and a bridge entry point.** The originals store exposes
   keyed get/put, not a last-result lookup. Add a small versioned last-completed
   reference after successful original persistence, plus a bridge operation to
   register its verified image/latent before inference. A missing/corrupt record
   falls back to normal arrival. Restore the last face without overwriting unrelated
   current/default faces or resurrecting source files; retain usable input IDs and
   settings. Do not make blocked storage delay visible first-load UI.
4. **Nonblocking edits require results to merge safely.** Requests already snapshot
   inputs, but snapshots alone do not prevent stale outputs. The bridge's batch
   commit clears the face map and URLs. Scheduler results must merge by face ID and
   revision; removed/edited faces cannot reappear on completion. A morph request
   snapshots face order, input revisions and settings; later edits invalidate that
   result's applicability, without changing in-flight computation silently.
   Cancel one face/queued item separately from cancelling the active morph.
5. **Analytics interruption is not necessarily a terminal product outcome.**
   Reporting currently emits interrupted on tab hidden, yet work may later finish;
   its terminal callback can therefore yield interrupted and completed for one
   run. Give aggregate request outcomes an idempotent lifecycle separate from
   diagnostic visibility observations. Hidden alone is not proof of abandonment.
   Preserve detailed diagnostics history without double-counting requests.
6. **No photo pills does not require moving Remove.** The draft unnecessarily moved
   every action outside the image, conflicting with the earlier requested close
   control placement. Preserve the small image close control; remove photo-label
   pills. Compare can be an accessible adjacent hold action.
7. **Delivery scope spans several independent increments.** Layout, scheduler,
   photo detection/cropping, restoration, infill/scrubbing, analytics and catalogue
   materialization are substantive separate work. Promote completed qualified
   increments and track the rest explicitly; do not label the whole plan done
   after the first UI promotion. Full catalogue and native-desktop research must
   not obscure delivery of the agreed candidate improvements.

## Not fully checked — no readiness claim yet

- **Photo decoder/detector:** no prototype has demonstrated bounded peak decode,
  original-detail recrop or orientation-safe selected-face mapping across routes.
  Inspect detector bindings and validate real fixtures before promising automatic
  acceptance of every large image. Keep current guarded crop path during rollout.
- **GA operations:** live code inclusion was checked and 11 analytics tests passed
  earlier; GA receipt, current registrations/retention, automatic metadata privacy
  and a percentile-capable reporting path have not been confirmed. Dashboards are
  planned, not operating evidence.
- **Actual responsive UI:** this review did not render the revised layout at phone/
  desktop widths or exercise keyboard/touch hold and live cancellation.
- **Device performance:** no new physical iPhone, GPU concurrency, native binary or
  sustained-memory evidence was collected. Parallel heavy work remains deferred;
  iPhone hardware evidence is not a candidate promotion gate.

No new operator decision is required for the corrections above. The unchecked
items require implementation investigation and verification, rather than treating
missing evidence as either a pass or a reason to block all development.
